## 設計原則

- Atomic Design: コンポーネントの再利用性を高めるため
- Custom Hooks: ビジネスロジックとUIを分離

## コンポーネント

以下のディレクトリにコンポーネントを作成する。
新規ファイルを作成した場合、およびファイルに関数を追加した場合は、対応するテストファイル・テストケースを必ず作成すること

| ディレクトリ | 役割 | 備考 |
|---|---|---|
| `components/ui/` | 汎用的なUIパーツ | ボタン・インプットなど再利用性の高いコンポーネント |
| `components/features/` | 機能単位のコンポーネント | 機能ごとにサブディレクトリを作成（例: `features/books/`） |
| `components/layouts/` | レイアウト系 | ヘッダー・フッターなどページ全体の構造に関わるコンポーネント |

- ボタン・インプット・バッジなど汎用的なUIは必ず `components/ui/` に切り出す
- テストファイルはコロケーション方式で対象ファイルと同じディレクトリに配置し、ファイル名は`*.test.tsx`とする

## 入力フォーム

フォームはreact-hook-formとzodを使用して実装すること。  
フォームの状態管理はコンポーネント側で行い、カスタムフックはAPI呼び出しとローディング・エラー状態の管理に専念すること。

## カスタムロジック

以下のディレクトリにカスタムロジックを作成する。

| ディレクトリ | 役割 | 備考 |
|---|---|---|
| `hooks/` | カスタムフック | 機能ごとにファイルを作成（例: `useBooks.ts`） |
| `api/` | APIリクエスト処理 | 機能ごとにファイルを作成（例: `books.ts`） |
| `utils/` | 共通ロジック | |

- テストファイルはコロケーション方式で対象ファイルと同じディレクトリに配置し、ファイル名は`*.test.ts`とする
