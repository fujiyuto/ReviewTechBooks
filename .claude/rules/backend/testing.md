# テスト方針

## 基本方針

- テストフレームワークにはVitestを使用する
- テストファイルはコロケーション方式で対象ファイルと同じディレクトリに配置する
- ファイル名は`*.test.ts`とする
- 新規ファイルを作成した場合、および関数を追加した場合は対応するテストを必ず作成すること

## テスト対象

### サービス層（`services/`）

ビジネスロジックのテストを中心に行う。

- 正常系：期待するデータが返却されるか
- 異常系：エラーが正しくthrowされるか
- リポジトリはモックに差し替えてテストする

### リポジトリ層（`repositories/`, `infrastructure/`）

- 基本的にテスト不要
- 必要に応じてSupabaseのテスト用クライアントを使用する

### ルート層（`routes/`）

- サービス層をモックに差し替えてテストする
- 正常系・異常系のレスポンス形式・ステータスコードを確認する
- バリデーションエラーが正しく返却されるかを確認する

### ミドルウェア（`middleware/`）

- 認証ミドルウェアが未認証リクエストを正しく弾くかを確認する

## テストの書き方

- `describe`でテスト対象をグループ化する
- 正常系・異常系でグループを分ける
- テストケース名は「何をしたときに何が起きるか」を明示する

```typescript
describe('BookService', () => {
  describe('getBookById', () => {
    it('returns book when book exists', async () => {})
    it('throws NotFoundError when book does not exist', async () => {})
  })
})
```
